# 帕尼尼 · 个人执行监督系统

一个**没有服务器、纯本地**的个人执行监督员。

它的职责不是取悦你，而是帮你减少拖延、克服启动障碍，把计划变成行动。

> 计划不是成果，意图不是行动，承诺不是完成。

---

## 快速开始

```bash
npm run serve          # 或 python tools/serve.py 8000
# 打开 http://127.0.0.1:8000
# 右上角「设置」→ 填 DeepSeek API Key → 点「测试连接」
```

只需要一个 DeepSeek API Key（[platform.deepseek.com](https://platform.deepseek.com) 申请）。

**没有构建步骤。** 测试工具（jsdom、fake-indexeddb）是可选的，只有跑测试才需要 `npm install`。

### 为什么用 `tools/serve.py` 而不是 `python -m http.server`

```bash
npm run serve    # 禁缓存 + 正确 MIME，推荐
python -m http.server 8000   # 能用，但有两个坑
```

1. **`python -m http.server` 不发 `Cache-Control`。** 浏览器会对资源按启发式规则自行缓存，**ES 模块一旦被缓存，改了代码刷新还是旧的** —— 表现为"改了没生效"或"时好时坏"，极难排查。`serve.py` 发 `no-store`。
2. 它把 `.mjs` 当 `text/plain` 返回，浏览器加载 ES 模块时严格检查 MIME 会直接拒绝。`serve.py` 也修掉了。

### 出了问题怎么定位

**设置 → 底部「开始诊断」。** 它用真实请求分步检查，并把**原始响应**抓下来：

```
✅ API Key 已填写
✅ 工具定义结构检查        40 个工具结构合法
✅ 鉴权与网络（GET /models） 200  可用模型：deepseek-chat、deepseek-reasoner
✅ 基础对话（非流式、不带工具） 模型回了「通」
✅ 带工具定义（非流式）      接受 17 个工具定义，无报错
✅ 流式 + 带工具（应用实际路径） 收到 SSE 数据流，含 delta 分片
✅ stream_options.include_usage 支持
结论：全部通过。
```

**哪一步先失败，问题就在哪一层**，结论里会直接说。点「复制报告」可以把整份报告带走。

数据全部存在你浏览器的 IndexedDB 里，API Key 只在本机 localStorage，页面直连 DeepSeek 官方接口，中间没有代理。

## 三个"必须由代码独占"的能力

这是整个系统设计的核心判断：

> **凡是"模型无法可靠记住"或"模型无法诚实声称"的东西，都必须落成数据和代码。**

### 1. 真实计时器

提示词要求"不得伪造计时结果"、"不得声称拥有后台计时能力"——但**模型没有时钟**。让它承担计时，它只能编。

所以计时是真做的：`startedAt` 写进 IndexedDB，**页面刷新、关掉重开都还在跑**，结束时的耗时来自墙钟而不是自报。用户自报的时间和计时结果**并排存两列**，不一致时系统能发现，不抹平。

副产品：攒够样本后能算出你的**时间感知偏差**（"平均比预估多用 40% 的时间"）。

### 2. 能力声明由代码生成

系统提示词里那段「平台实际能力」**不是手写的**，是从实际配置算出来的：

```
✅ 页面打开时：能计时、能读写本地记录
❌ 页面关闭后：什么都不做，没有后台监控
❌ 无法主动发消息（通知功能未实现）
❌ 你没有时钟（时间来自设备本地时钟）
```

这样结构上杜绝了"提示词写着能提醒、实际没实现"的漂移。将来真做了通知，改代码就同步了。

### 3. 不虚构历史

积分表为空时，注入的是「**尚未建立积分账本**」而不是 `0`。同理适用于打卡、复盘、规划——**没有数据就说没有，不給默认值让模型圆场**。

## 代码级 vs 模型级

你的指令分成两类，分工明确：

| 类型 | 谁执行 | 例子 | 理由 |
|---|---|---|---|
| **代码级** | 程序直接跑 | 开始/结束计时、生活打卡、查看积分、导出、跳面板 | 有确定答案的事，代码答更快更准，且**零 token** |
| **模型级** | 帕尼尼 | 小黑屋、任务拆解、拖延分析、规划、SOP、总结 | 本来就需要判断力 |

一条消息的完整路径：

```
1. 正则识别意图                                    ← 零 token
2. 若是「查看类」→ 纯 UI 切换，直接结束，不调模型
3. 若是「计时/暂停/导出」→ 代码先执行，拿到精确结果
4. 把结果作为「事实」注入上下文，再交给模型说话
```

第 4 步是关键：模型会说"你已经跑了 37 分钟"，而这个数字是**代码给的**，不是它编的。

**设计要点：**

- **左侧竖向导航带文字标签**（默认 184px），不是纯图标条 —— 不用悬停就知道每一项是什么。全部使用**内联 SVG 线性图标**，无 emoji、无图标字体、无 CDN 依赖。
- **导航和面板都能拖动改宽度**，把手在各自的右边缘。有上下限防止拖失控，**双击复位**，宽度存 localStorage。
- **两者也能一键收起**：导航收成 52px 图标条，面板收成 26px 把手，对话区拿回全宽。
- **顶栏有「＋ 新对话」**，点一下就开一条新对话（不弹窗、不确认）；旁边「对话列表」用于切换和删除。
- **对话区宽松、列表区紧凑**，刻意分开调：对话 15px/1.78 行高，长文读着不累；列表 13px/1.5，一屏能看更多。
- **帕尼尼的消息没有气泡底色**，只有用户消息是右对齐的浅蓝气泡。因为他是监督员，输出通常是成段文字，套气泡反而挤。
- **出错时不会只丢一句提示**：错误块会显示 HTTP 状态、可复制原始响应，并告诉你「设置 → 开始诊断」。

| 🏅 积分 | 账本流水、待确认标记、奖励兑换 |
| 🗺 规划 | P-001 自动编号、可行性检查、任务项勾选 |
| 📘 SOP | 12 项结构 + **一分钟启动版** |
| 🔍 复盘 | 拖延模式统计（A-H）、沉淀的有效策略、复盘明细 |

### 有些动作必须你自己按

模型可以提议，但**按下开始键的必须是你本人**。

看这条真实对话：

```
🔧 timer_start(task=根据面经学习 agent 项目 plannedMin=25)
✓ timer_start(根据面经学习 agent 项目)
…
计时开始——任务已建，计时开始。
```

模型自己决定了你接下来 25 分钟干什么，然后告诉你已经开始了。这跟 §21「用户拥有最终决定权」直接冲突——而且光把这条写进提示词**根本拦不住**，模型照样会顺手替你按。

所以代码层面分了两类：

| 类型 | 处理 | 例子 |
|---|---|---|
| **记录类** | 直接执行 | 记学习、记打卡、写记忆、建任务 —— 你在转述自己做了什么，模型只是照抄 |
| **承诺类** | **变成按钮等你点** | 开始/结束计时、设定今日关键任务、暂停或恢复监督、删除任务/记忆、扣分、兑换奖励 |

承诺类动作渲染成对话区下方的确认卡片：

```
▶ 开始计时                                    [确认]  [不用]
  开始计时：根据面经学习 agent 项目　计划 25 分钟
  这是你的决定，点一下才会执行
```

配套的三件事：

- **待确认项存在数据库里**，刷新页面还在。否则模型说的话会变成指向一个已经消失的按钮的死引用。
- **提示词里明确写了**：这类动作用提议语气（"点下面的按钮"），**绝对不能说成"已开始"**。模型知道它没执行。
- **同一个工具只保留最新一条**，免得模型一轮里调两次就冒出两个按钮。

> 顺带一提：你输入「开始计时」这种**代码级指令**时，仍然是立刻执行的——那是你自己下的命令，不需要再向自己确认一次。

### 记录面板：看清某一天，并且能改

专注记录光记下来不够，你还得能回头看、能修正。所以有一个「记录」面板：

```
‹  2026-10-10  ›   回到今天
10月10日 周五
  127 分钟专注   4 段   2 个任务   完成 1 项
  [＋ 补记专注]  [＋ 补记学习]

专注记录  4
08:00 – 08:33  推导梯度下降                    33  分钟
                [计时] [已修正]
09:15 – 09:52  写论文引言                      37  分钟
                [自报] [自报差 +8 分]
12:00 – 12:12  忘开计时器了                    12  分钟
                [补记]

学习记录  2
10:20  极大似然估计                            40  分钟
       看完第 3 节并手推了一遍
       卡点：对数动机不清楚
```

**点任意一条就能改。** 可以改起止时间、时长、关联任务、备注、完成情况，也能删。

**两个诚实的设计：**

- **改过的记录会标「已修正」**，并且记下修正时间。它不会假装自己从来没被动过——原始记录和人工修正过的记录，不该长得一模一样。
- **专注时长和学习记录时长分开显示，不合并成一个总数。** 两者经常同时存在（你开着计时器，同时又让帕尼尼记一条学习记录），加起来就是重复计算。

**补记是为了"忘了开计时器"这种情况。** 时长留空就按起止时间自动算，表单里会实时告诉你它准备按哪个数记。

**「今日动态」里的条目也能点开编辑**，看到不对的一条，点一下就改。

### 左侧栏什么时候更新

这是被问过的问题，所以明确写下来。**六个时机：**

| 时机 | 说明 |
|---|---|
| **每轮对话结束时** | 最主要的时机。刷新在按钮恢复成「发送」**之前**完成，所以你看到"可以输入了"时，侧栏已经是新的 |
| 回合进行中，工具改了数据 | 每个写入类工具返回 `refresh: true`，触发一次 300ms 防抖刷新 |
| 任何弹窗保存后 | 任务、知识点、规划、SOP、打卡、余额 |
| 页面从后台切回前台 | `visibilitychange`，因为计时条要立刻对上 |
| 点面板标题旁的**刷新按钮** | 手动兜底 |
| 切换面板 | 切过去时用最新数据渲染 |

面板标题右边会显示「**HH:MM 更新**」，刷新时面板会**闪一下蓝**——这样"更新发生了"是看得见的，不用靠猜。

**「今日」面板有「今日动态」时间线**，把今天发生的事按时间列出来：学习记录、计时、完成的任务、打卡。这是刻意加的——因为大部分对话结果（`log_study` 建的知识点、`save_memory`）原本只在别的面板可见，你停在默认的今日面板聊完会觉得"没反应"。

> **没有"指令列表"页面。** §17 明确要求"不要要求用户死记指令名称"，那摆一张指令速查表就是自相矛盾——而且它会把「代码级/模型级」这种实现细节漏给用户看。所以问帕尼尼"你能做什么"，他会用自己的话讲，并且只能讲「平台实际能力」那节里写明的能力（不会承诺主动提醒之类做不到的事）。

## 表达强度与安全边界

设置里有 1-5 档强度：

| 档 | 风格 |
|---|---|
| 1 | 温和陪学 |
| 2 | 偏温和但要结果 |
| 3 | 冷峻克制（不说脏话） |
| 4 | 强硬（允许冷嘲） |
| 5 | 完全放开 |

默认 5/5，粗口默认授权。

**但下面这些是硬约束，任何强度下都不会越过的**（写在提示词的"最高优先级"段，代码层面的措辞也固定不可覆盖）：

- 不攻击你的人格、身体、身份或心理健康状况
- 不用羞辱代替真正的任务管理。冷嘲指向行为和借口，不指向人
- 不剥夺睡眠、饮食、医疗支持或基本生活需求作为惩罚
- 不擅自执行真实的账户封锁、设备限制——**积分扣分只是一行记录，系统没有、也无法封锁你的设备**
- 不诊断疾病、不建议调整药物
- 不把 ADHD 相关困难归结为懒惰
- **不把你没回复视为任务失败**

### 危机暂停

任何一句类似"暂停监督"、"我现在状态很差别催我"的话，或者帕尼尼自己判断你情绪崩溃了，都会触发暂停：

- 写入 `suspendUntil`
- 之后每轮注入一条**覆盖全部其他规则**的强指令
- 暂停期间：不催任务、不算积分、不做复盘、不用冷嘲、**语气强度设定直接失效**
- 由你说"恢复监督"解除

## 数据安全

浏览器数据随时可能因清缓存、换浏览器、换电脑而消失。**手动导出靠不住，因为人会忘。**

点「备份」→「选择镜像文件」，之后每次变更自动写入（2 秒防抖）。这个文件是普通 JSON，可以用 Git 管你的记录历史。

注意：浏览器每次重新打开页面都会重置文件写权限，需要点一下按钮重新授权——这是浏览器的安全限制，绕不过去。

### 迁移到别的 AI

顶栏「导出」会生成一份**自包含的 Markdown**，包含 11 个章节：用户档案、任务与状态、计划与实际时间、生活打卡、积分账本、规划、SOP、复盘与拖延模式、知识点、下次继续监督的事项、数据说明。

整份贴进任何一个 AI 会话，就能接着监督。文档里明确区分了"代码算出的事实"和"未记录"，不含推测。

npm run verify:all     # 四个都跑
npm run cost:tools     # 量工具 token 成本
npm run cost:prompt    # 量提示词各段占比
npm run verify:served  # 需要先起服务器

## 踩过的坑

**1. `.mjs` 扩展名会让应用白屏。**
浏览器加载 ES 模块时严格检查 MIME，而 `python -m http.server` 把 `.mjs` 当 `text/plain` 返回，直接拒绝执行。所以 vendor 里是 `dexie.js`。用 `python tools/mime-check.py` 可复现。

**2. 长期记忆的注入曾经被整个漏掉。**
重写 `memory.js` 时，`fmtMemories` 和 memories 的读取都丢了——结果是"分层记忆"里最该常驻的一层，只剩下 `search_memory` 检索才拿得到。**冒烟测试抓到了这个。**

**3. SOP 校验有个空数组漏洞。**
`!rec[k]` 对空数组返回 `false`（`![]` 是 `false`），所以 `steps: []` 能通过"必填"校验。改成显式的 `isBlank()`。

**4. 测试里不能硬编码日期。**
最初用 `2025-01-10` 当"未来的截止日期"，日期一过就变成逾期，测试自己失败。

**5. 不要相信关于 CORS 的二手结论。**
网上大量文章说"DeepSeek API 不支持浏览器直连"，**实测是错的**——它会回显 Origin，预检和错误响应都带 CORS 头。自己跑 `npm run probe:ai` 验证，30 秒。

**6. 「指令列表」页面是个设计错误。**
最初做了一个指令速查面板，还把每条标成「代码级/模型级」。但 §17 自己写着"不要要求用户死记指令名称"——摆一张表就是自相矛盾，而且代码级/模型级是**我的架构内部分工**，跟用户毫无关系。已删除：问"你能做什么"，帕尼尼用话讲，且只能讲能力声明里写明的真实能力。

**7. 一个笔误让整个发送链路挂掉，而 263 项断言全绿。**
`agent.js` 里写成了 `buildMessages({ sessionId, ... })`，变量实际叫 `session`，应为 `session.id`。运行时抛 `ReferenceError`，界面表现为"发消息没反应"。

**根因不是笔误，是测试的策略错了**：所有断言都直接调 `memory.buildMessages()`，从来没有真正执行过 `runTurn`（它需要网络请求）。单元全绿、集成全坏。修法就是加上 `tools/dom-test.mjs`。

**8. 绝不要用 PowerShell 的 `-replace` / `Set-Content` 改这个项目的源文件。**
我用它做了一次批量替换，PS 5.1 默认 ANSI 编码把 UTF-8 中文全变成乱码，而且**乱码吞掉了换行符**，导致下一行的 `if (...)` 被吃进上一行的注释里，产生极难定位的语法错误，文件甚至变成非法 UTF-8 读不出来，只能重写整个文件。用编辑器或 `edit` / `write` 工具。

**9. 测试里的固定 `sleep` 和 `busy` 竞态。**
DOM 测试最初用 `wait(1500)` 等工具调用回合，机器负载高时不够，随机失败。改成等真实条件后仍失败——因为**"助手气泡出现"不等于"回合结束"**：气泡在流式中途就存在，而 `send()` 的 `finally` 还要 `await refreshAll()`。在那之前 `busy` 仍是 `true`，下一条消息会被静默丢弃。正确信号是发送按钮文案恢复。**连续跑 4 次全绿才算稳。**

**10. `fetch` 没有超时，会把应用卡死。**
最初 `deepseek.js` 里没有任何超时。一旦某个请求挂住（网络抖动、服务端不响应），`runTurn` 永远不会 resolve，`busy` 就永远停在 `true`，**之后每一条消息都会被静默丢弃** —— 症状正是"突然就不回答了，重启才恢复"。

修法是两层看门狗：拿到响应头有 30 秒上限，两个数据分片之间超过 90 秒就认定连接已死并给出明确提示。外部中断信号和内部超时要能区分，否则用户点"停止"会被误报成超时。

**11. 诊断模块里裸用 `location` 会自己把自己打断。**
`diagnose.js` 里写了 `location.protocol`，但某些运行环境没有这个全局（测试沙箱就没有），直接抛 `ReferenceError`，诊断卡在第 5 步。改用 `globalThis.location?.protocol ?? '未知'`。这是 DOM 测试抓到的——没有那几十项断言，这段代码会带着 bug 上线。

**12. 专注记录只能看今天，而且不能改。**
用户提的："不知道哪里可以看具体一天的专注记录，应该是要有这个地方的，然后可以编辑。"

确实缺。时间记录当时只在「今日动态」里露一下，且仅限今天、只读。加了「记录」面板：日期前后翻 / 日期选择器 / 一键回今天，明细可点开编辑、可补记、可删。

顺带修掉一个**当时还没暴露的缺陷**：`task.actualMin` 原本是累加出来的（`logTimeEntry` 里做加法），记录一被编辑或删除就会算错。改成**从时间记录派生**。这个问题在加编辑功能之前不会显现——**因为以前根本没有"改"这个操作**。

**13. 「说了称呼但一直没更新」：一个优化把能力悄悄藏掉了。**
用户反馈输入称呼后一直没生效。查下来是**三件事叠在一起**：

- **主因：工具分组下发漏了 `update_profile`。** 为了省 token，我按意图正则分组下发工具，profile 组的正则里有"叫我"却没有"我叫"。用户说"我叫小明"就匹配不上，`update_profile` 根本没进请求 —— **模型想存也存不了，而它不会说"我没有这个工具"，只会说"好的小明"，然后什么都没发生。**
- **次因：顶栏标题只在启动时设了一次。** 改了"怎么称呼监督员"，界面上看不出来。
- **三因：没有任何回执。** 存是存了，但用户得自己翻档案面板才知道。

修法：**移除分组下发，每轮全量下发**（`node tools/tool-cost.mjs` 复核过成本：约 370 token 当量）；顶栏标题跟着档案实时更新；工具可以带回一句给用户看的回执。

**教训：** 这种 bug 最难查，因为它**不报错**。模型的行为看起来完全正常（它答应了你的要求），只是它手里根本没有那个工具。**任何"按条件裁剪能力"的优化，都要先问一句：条件判断错了会怎样？** 这里答案是"静默失去一项能力"，那么它就不该存在。省 token 要从**上下文体积**下手，不能从**可用能力**下手。

**14. 同一个 bug 还活着：正则把"能力"当成了"开关"。**
修完"称呼"之后顺手查了一遍：`commands.js` 里还有 19 条正则，其中 8 条决定"注不注入流程段落"。实测 8 条常用说法**漏 4 条**：

| 说法 | 结果 |
|---|---|
| 「我想开始学线代了」 | ❌ 正则要的是"开始学习"这个连续串 |
| 「我最近老是这样拖着」 | ❌ 正则里只有"总是拖""又拖延" |
| 「我想把这件事做成流程」 | ❌ 正则里只有"操作流程/制定流程" |
| 「你都能干啥」 | ❌ 正则里是"能干什么" |

漏掉的后果是模型拿不到用户自己定下的那套步骤，只能即兴发挥。修法是**流程全量注入**——各段落开头本来就写着它的触发条件，模型按当下情况选一段走，比正则猜准得多（成本约 200 token 当量，`node tools/prompt-cost.mjs` 可复核）。

**同时发现的更严重问题：我在提示词稳定层里嵌了当前时间。**
能力声明里写着"当前时间由代码写入快照（2026-10-10 14:32）"，而能力声明位于稳定前缀中段。这行的字符串**每分钟都在变**，导致 DeepSeek 的上下文缓存**从那一行往后全部失效** —— 档案、长期记忆、工作准则、流程段落每一轮都按全价重新计费。改成"时间写在下面「当下的情况」一节里"，并把段落按变化频率重排（纯静态的流程放到最前）。

**教训（两条）：**
1. **任何"按条件裁剪能力"的优化，先问"条件判断错了会怎样"。** 如果答案是"静默失去一项能力"，就别做。现在的判据是可执行的：**每一条代码动作，都必须有一个工具能做同样的事**，冒烟测试里有断言守着。
2. **提示词里绝不能出现每轮都变的内容**，尤其是时间。缓存按前缀匹配，前面一变后面全废。测试里有一条断言扫描稳定层，发现时间戳就失败。

**15. 侧栏"没更新"，其实是两个体验缺陷叠在一起。**
用户反馈"聊完左侧栏没更新"。写了 DOM 测试去验证，**机制本身是好的**——停在哪个面板就会刷新哪个，9 项断言全过。真正的问题是：

- **顺序错了**：`setBusy(false)` 排在 `await refreshAll()` 前面，所以按钮已经显示"发送"、侧栏却还是旧数据。
- **默认面板看不到对话结果**：`log_study` 建的知识点只在任务面板，`save_memory` 哪儿都不显示。用户停在默认的「今日」面板，聊完确实没有任何变化。

修法：调整顺序（先刷新再恢复按钮）；面板标题加「HH:MM 更新」时间戳、刷新时闪蓝、加手动刷新按钮；给「今日」加**今日动态时间线**（学习记录 / 计时 / 完成的任务 / 打卡），让对话结果在默认面板上直接可见。

**教训：** 用户说"没更新"时，要先区分是**机制没跑**还是**跑了但看不见**。我第一反应是去查代码对不对，更该问的是"他能看到什么"。

## 关于提示词里的流程

HOPE、小黑屋、规划、SOP 这四段流程加起来比整个人设还长，但每轮通常只用到一段。所以**按需注入**：

```
第一层（永远注入，放最前吃缓存）：
  人设 + 安全规则 + 语气强度 + 能力声明 + 档案 + 长期记忆 + 工作准则
第二层（永远注入，篇幅小）：
  今日关键任务 + 任务板 + 积分 + 当下信号
第三层（按需注入，放在最后）：
  HOPE / 小黑屋 / 规划 / SOP / 拖延识别 / 完成核验
```

这样既省钱，也让模型在需要时才看到完整步骤，减少走错分支。

同理，41 个工具**每轮全量下发**。

> 这里曾经做过"分组按需下发"（核心 14 个常驻，其余按意图正则匹配），**已经移除**。
> 因为正则必然漏：用户说"我叫小明"，而 profile 组的正则里只有"叫我"，`update_profile`
> 就没被下发 —— 模型想存也存不了，它不会说"我没这个工具"，只会说"好的小明"，然后
> 什么都没发生。用户看到的是"说了称呼但一直没更新"。
>
> 量过成本：全量 ≈ 7000 token，核心 14 个 ≈ 2300 token。但工具 schema 是稳定前缀会被
> 上下文缓存命中，实际增量只相当于约 **500 token**。
> **用 500 token 换"不会静默丢能力"，很划算。** 跑 `node tools/tool-cost.mjs` 可以复核。
>
> 省 token 的正确姿势是**别把历史日志全塞进 prompt**（这才是分层记忆在解决的问题），
> 而不是把工具藏起来一半。

### 那"怎么确保模型选对工具"？

**没有代码在识别工具了 —— 选择和调用交给模型的 function calling。** 所以唯一的依据是
**工具描述本身**。描述的质量直接等于模型能不能选对，所以它被当成需要验证的工程产物来对待。

`node tools/tool-audit.mjs`（已进 `npm run verify` 门槛）查三件事：

1. **每个工具是否说清"什么时候该调我"** —— 而不只是"我干什么"。
   `delete_task` 曾经的描述只有 4 个字"删除任务。"，模型完全可以自己判断某个任务过时了就删掉。
   现在写的是"**只在用户明确要求删除时调用**，不要因为觉得某个任务过时就没用就自己删 —— 那是他的任务"。
2. **参数说明、type、必填项是否齐全。**
3. **易混的兄弟工具是否互相点名。** 这是废弃正则之后的主要风险：

   | 工具 | 描述里明确写了 |
   |---|---|
   | `log_study` | 记学习内容用这个；**只想补时长用 `log_time_entry`** |
   | `timer_stop` | 结束计时用它；**不要用 `log_time_entry` 代替**（那会把真实计时降级成自报） |
   | `set_task_state` | 只改状态用这个；**改其他字段用 `save_task`** |
   | `save_review` | 复盘结论用这个；**通用长期事实用 `save_memory`** |
   | `forget_memory` | **只在用户明确要求删除时调用**，不要自己判断哪条没用 |
   | `open_panel` | 他随口提到某事时**不要调** |

审计起初查出 **41 个工具里 27 个没说清触发条件**，现在 0 个。

**但要说清楚：这只是形式检查。** "模型会不会选对"无法自动测试 —— 测试用的是桩数据，
验证的是"某次调用能正确执行"，不是"模型做出了正确选择"。这件事只能靠真实使用观察。
所以界面上**故意保留工具调用轨迹**，你能看见它到底调了什么、失败在哪。这是唯一可靠的一手信息，
有问题直接看那里。

### 出错时的三层兜底

模型选错了也不是没有救：

| 层 | 机制 |
|---|---|
| 参数错误 | 工具返回可读错误，**回灌给模型让它自己改参数重试**，不让整个回合挂掉 |
| 越权动作 | 承诺类动作（计时、删除、扣分…）变成确认按钮，**你能在最后一刻拦下** |
| 数据一致性 | 状态时间、任务实际耗时、SRS 排期、可行性检查全部由代码算，不让模型报数 |

唯一没兜底的是"选错但合法"—— 比如该记 `log_study` 却记成了 `log_time_entry`。
那种只能靠描述写清楚（上面第 3 点）和你看轨迹发现。

### 正则现在只负责"快路径"，不负责"能力"

`commands.js` 里还剩一组正则，但它们**已经降级**：命中了就省一次模型往返、立刻执行；
没命中就把话交给模型，模型手上有对应的工具，照样能做成事。

| 代码动作 | 兜底工具 |
|---|---|
| `timer_start` / `timer_stop` | 同名工具 |
| `suspend` / `unsuspend` | `suspend_supervision` / `resume_supervision` |
| `panel_*`（6 个面板） | `open_panel` |
| `export_md` | `export_records` |

**判据：每一条代码动作，都必须有一个工具能做同样的事。** 否则一旦正则漏了，用户就会
遇到"说了但没反应"。冒烟测试里有一条断言专门守着这个不变量。

流程段落不再用正则挑 —— 以前按关键词决定"注不注入 HOPE / 小黑屋 / 规划 / SOP"，
实测 8 条常用说法漏 4 条（"我想开始学线代了"匹配不到 start，"你都能干啥"匹配不到 help）。
现在**全部流程始终注入**，各段落开头就写着它自己的触发条件，由模型按当下情况选一段走。

跑 `node tools/prompt-cost.mjs` 可以复核流程的 token 占比。
