## 修复（1.3.3）

### 通知页的时间点不了、权限申请不到

两件事其实是同一个原因：**时间框只有在「启用手机通知」成功之后才可编辑**，而那个开关一旦失败就会弹回去。

- 网页端：开关必然弹回（网页本来就发不了通知），时间框因此永远是 `disabled` —— 点上去毫无反应。
- Android 端：只要权限没到手（首次拒绝、连点两次被系统永久拒绝、桥没响应），开关也弹回，时间框跟着锁死。

现在改成：

1. **时间永远可编辑**，不管开关是什么状态、权限有没有给。想先排时间就先排，保存时会照实记下来。
2. **加了独立的「申请通知权限」按钮**（只在 Android App 里显示）。开关负责"启用"，按钮负责"要权限"，两个动作分开，不会再出现"点了半天不知道点的是哪一个"。
3. **失败写在你正在看的那一行**：授权失败的原因同时写进开关下面那行小字、检查区的状态行和 toast。以前只丢一个 7 秒后消失的 toast，很容易被当成"没反应"。
4. **被系统永久拒绝也有出口**：Android 13+ 用户连拒两次后系统不再弹框，`requestPermissions()` 只会立刻返回 denied。新增原生方法 `AppSettings.openNotificationSettings()`，直接跳到本应用的系统通知设置页，用户自己去打开就行，不用翻三层菜单。
5. **新增诊断行**：检查区最后一行固定写「外壳 android · 插件 可用 · 权限 已允许 · 精确提醒 已允许」。以后再说"点了没反应"，这一行就能定位是哪一环断了（外壳没起来 / 插件没注册 / 权限没给 / 精确提醒没开）。

### 为什么不直接把开关做成"网页也能勾上"

那会让网页上显示"已启用手机通知"，但其实一条都发不出去 —— 比弹回更误导。网页端现在明确写：可以设置时间，提醒要装 Android App 才会真的发出来。
